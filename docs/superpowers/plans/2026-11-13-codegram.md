# Codegram Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Use subagent-driven-development only if the user selects delegated execution. Steps use checkbox syntax for tracking.

**Goal:** Deliver a polished, working iOS/Android portfolio social app with media carousels, social interactions, and mutual-follow messaging.

**Architecture:** Keep the Expo Router application and replace starter screens with protected native tabs and stack detail screens. Clerk manages authentication; Convex manages authenticated queries, mutations, scheduled cleanup, reactive messaging, and file storage. App profile data lives in Convex and is initialized from Clerk once.

**Tech Stack:** Existing Expo ~58.0.24, Expo Router ~58.0.31, React 19.3.0, React Native 0.88.1, TypeScript ~6.0.3; NativeWind stable v4 candidate; Clerk Expo SDK; Convex; Expo image picker/video/secure storage/development client; Vitest with convex-test; React Native Testing Library where compatible.

**Spec:** [Codegram v1 specification](../specs/2026-11-13-codegram-design.md). It records interview decisions separately from proposed defaults.

## Global Constraints

- iOS and Android development builds; four tabs: Home, Messages, Explore, Profile. No web deliverable or public store submission.
- Keep Expo 58 first. Do not silently substitute NativeWind, Clerk, Convex, or native tabs. Stop the compatibility task with evidence if the chosen stable pairing fails.
- Use npm and the existing package-lock.json; install dependencies through `npx expo install`. Check matching Expo 58 documentation before using Expo APIs; pin newly selected package versions after validation.
- Five media items maximum, 10 MB per image, 25 MB and 30 seconds per video. Interpret MB as 1,000,000 bytes; reject values above the limit.
- Home is reverse chronological own/followed posts. Mutual following is required for every message send, including existing conversations.
- No paid upgrade, third-party service substitution, or store submission is included. Credentials belong in local/service environment configuration, never source control.
- Run `npm run lint` and `npx tsc --noEmit` for each completed task; fix configuration so these commands are real checks. Commit each independently verified task; do not commit secrets or generated native projects.

## Structure and shared contracts

- Routes: `src/app/_layout.tsx` owns providers/auth gates; `(auth)/sign-in.tsx`, `onboarding.tsx`, `(tabs)/{index,messages,explore,profile}.tsx` with a native-tab layout. Stack routes: `posts/[postId].tsx`, `users/[userId].tsx`, `conversations/[conversationId].tsx`, `create-post.tsx`, `edit-profile.tsx`, `settings.tsx`. Non-route logic stays outside `src/app`.
- UI/features: shared primitives in `src/components/ui`; grouped implementations in `src/features/{auth,profiles,posts,explore,messages}`; providers in `src/providers`. Reuse the native-tab component and theme where practical; replace starter CSS/theme mechanisms only where NativeWind integration needs it.
- Backend modules: `convex/{schema,auth.config,users,follows,posts,uploads,likes,comments,conversations,messages,accounts,http,crons}.ts`; shared authorization/validation in `convex/lib`. Generated Convex IDs and API definitions are the common types, not manually duplicated models.
- Tests: `convex/tests/*.test.ts`, pure client tests under the owning feature, and `docs/verification/codegram.md` for the two-device acceptance checklist. Backend tests use Vitest/convex-test; use a separate SDK-compatible component-test configuration if Vitest cannot load native components.
- Public functions accept argument objects. All IDs below are generated Convex IDs. Pagination uses Convex `PaginationOptions` / `PaginationResult<T>`, default page size 20. Common errors use stable codes: `UNAUTHENTICATED`, `ONBOARDING_REQUIRED`, `FORBIDDEN`, `NOT_FOUND`, `VALIDATION_ERROR`, `USERNAME_TAKEN`, `MUTUAL_FOLLOW_REQUIRED`, `ACCOUNT_DELETING`.
- Validation defaults: usernames lowercase ASCII `[a-z0-9_]{3,20}`; display name 1–50 trimmed characters; bio 0–160; caption 0–2,200; comments 1–1,000; messages 1–2,000. Reject whitespace-only required text. Username changes are allowed with atomic uniqueness enforcement.

## Review Focus

1. Concurrent username claims, follows, likes, and conversation creation must not create duplicates (Tasks 2, 3, 5, 6).
2. Interrupted uploads, duplicate publish attempts, and expired uploads must not publish partial posts or leak stored files (Task 4).
3. Unfollowing, signing out, or backgrounding during a conversation/video must revoke sending or pause playback promptly (Tasks 4, 6, 8).
4. Deleted content, stale deep links, and account deletion midway through pagination must show a usable unavailable state (Tasks 5, 7, 8).
5. Out-of-order read updates and retried message sends must neither erase unread state nor duplicate messages (Task 6).

- [ ] Add/run failing tests for nonparticipant access, non-mutual creation/send, concurrent conversation creation, duplicate message retries, unfollow immediately before send, refollow, and monotonic read positions. Assert delayed mark-read cannot mark a newer unseen message as read.

## Acceptance and unresolved gates

V1 is complete when all eight task deliverables pass, both native platforms complete the core journeys, backend ownership/mutual-follow tests pass, partial uploads are never visible posts, and account cleanup can recover after interruption. Build distribution and service setup must be reproducible from documented instructions.

The first native compatibility gate and provider credentials cannot be proved by this written plan. Exact new package versions are selected and locked in Task 1 after validation; changing the agreed stack or adding paid services requires a separate decision. Free tiers, original-file video support, prefix search, and the simple feed are explicit demo-scale defaults.
